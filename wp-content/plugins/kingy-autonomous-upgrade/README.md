# Kingy Autonomous Upgrade

Guarded extension for the existing WordPress/KALI property. **Not deployed; production adapters are unconfigured.**

Activation is inert. Explicit additive migration requires a verified backup restore assertion; individual features and assigned jobs then require opt-in flags. No new catalog, source registry, account service, inquiry route or mailing list is created. No paid generation is called.

Source includes the commercial workflow, device/native-account stack, immutable material changes, private operations view, evidence-gated companion preparation/publication, accessible Brief builder, safe outbox and Vancouver schedule rules. Author-owned existing cost logic and camera project schema are reused.

Read [completion record](../../../docs/autonomous-upgrade/REPORT.md), [architecture and adapter contract](../../../docs/autonomous-upgrade/ARCHITECTURE.md) and [release/rollback runbook](../../../docs/autonomous-upgrade/OPERATIONS.md) before installation. The local harness must never run on production.

```sh
node --test wp-content/plugins/kingy-autonomous-upgrade/tests/workflow.test.mjs
```

Browser/WordPress acceptance evidence and prepared content are retained under `docs/autonomous-upgrade/`. Passing local checks does not establish production access, publication, delivery or scheduler installation.
